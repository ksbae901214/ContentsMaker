# 연예쇼츠 — 설계·개발 기록 (036)

정치쇼츠 전용이던 파이프라인에 **연예 카테고리를 추가**한 작업의 설계 근거와
구현 내용. 경제·사회도 같은 구조로 함께 들어갔지만, 이 문서는 연예를 중심으로
쓴다. 개발일 2026-08-13.

---

## 1. 핵심 판단 — 새 파이프라인을 만들지 않는다

가장 먼저 정한 것. **연예쇼츠 전용 스크립트/모듈을 만들지 않고, 기존 V2.2 제작
표준에 `category` 축 하나를 관통**시켰다.

근거: 파이프라인을 뜯어보면 도메인에 의존하는 부분이 거의 없다.

| 구성 요소 | 연예에서 달라지나 |
|---|---|
| Remotion 렌더러 | ❌ 동일 |
| 38~42초 길이 캡 (035) | ❌ 동일 |
| 육성 클립 릴레이 구조 | ❌ 동일 |
| 40% CTA 자동 삽입 (035) | ❌ 동일 |
| TTS 합성·타임라인 조립 | ❌ 동일 |
| **소재 프레임 어휘** | ✅ 사퇴·부결 → 인정·하차·복귀 |
| **CTA 선택지 축** | ✅ 여당/야당 → 응원한다/이르다 |
| **제목 앵커** | ✅ 실명 (정치와 같음) |
| **소스 저작권 등급** | ✅ 공적 발언 → **방송사 저작물** |

즉 바뀌는 건 **검사 기준표**뿐이다. 컨베이어가 아니라 품질 검사 기준을 갈아끼우는
문제였고, 그래서 규칙 팩 하나(`scripts/shorts_domain.py`)를 만들어 카테고리로
조회하는 구조를 택했다.

**부수 효과**: `category` 미지정 = `political` 이므로 기존 정치 config 37개가
무변경으로 동작한다(실측: 차단 0 / 경고 0 / 렌더 기본값 변화 0).

### 035 프레임이 그대로 산다
"결과가 난 사건" 원칙은 도메인이 바뀌어도 유효하고, 어휘만 갈아끼우면 된다.

| | 결과어 예시 |
|---|---|
| 정치 | '13시간 만에 뒤집힌 표결' |
| 연예 | '9년 만에 복귀', '3시간 만에 번복된 열애 부인' |

## 2. 연예 규칙 팩의 내용

`scripts/shorts_domain.py` 의 `DomainRules["entertainment"]` (frozen dataclass).

```
결과어      인정 부인 결별 열애 이혼 재혼 은퇴 복귀 컴백 하차 퇴출 해지
            계약종료 사과 폭로 결국 끝내 만에 뒤집 확정 무산
CTA 예시    "이 복귀 ① 응원한다 ② 이르다"
고정댓글    "이번 복귀, 어떻게 보세요? ① 응원한다 ② 이르다 — 번호로 답글 👇"
제목 앵커   실명(persons)
배경색      #7e22ce / #4c1d95 / #000000  (보라)
emotion     funny   ← 문제 있음, 5절 참조
```

### 가드레일은 2단으로 나눴다

법적 리스크가 **분명한 것**과 **사람 판단이 필요한 것**을 섞으면 둘 다 무뎌진다.

| 단계 | 연예에 적용되는 것 | 동작 |
|---|---|---|
| **차단** `gate_domain_words()` | 없음 (경제 투자권유 전용) | `ValueError` — 렌더 전 fail-fast |
| **경고** `domain_warnings()` | 미확인 사생활 7종: 불륜·양다리·임신설·마약설·이혼설·사생활·루머 | 경고 출력 |
| **경고** | `source_channel` 미지정 (`require_source_channel=True`) | 경고 출력 |

연예에 하드 차단을 두지 않은 이유: "불륜"이라는 단어 자체가 금지어일 수는 없다
(공식 인정된 사안을 다룰 수 있다). 판단이 필요한 영역이라 경고로 두고 사람이
결정하게 했다. 반대로 경제의 투자권유는 문맥과 무관하게 위험해서 하드 차단이다.

둘 다 config `"domain_gate": "off"` 로 우회 가능 — 단 리스크는 본인이 진다.

### 업로드 체크리스트 (연예 전용 2항목 + 공통 3항목)
```
⚠️ 방송 클립 저작권 — 인용 최소화·출처를 화면/설명란에 명시했는가
   (연예는 이 채널에서 저작권 위험이 가장 큰 카테고리)
미확인 사생활·루머가 아니라 공식 입장/보도로 확인된 사실인가
+ 해시태그·길이 캡·CTA (전 카테고리 공통)
소재가 '설(說)'이 아니라 '결과가 난 사건'인가
```

## 3. 코드가 어디로 흐르는가

```
config.json  { "category": "entertainment", ... }
        │
        ├─ shorts_category.resolve_config_category()   # 검증, 미지정→political
        │      └─ record_category()                    # 성과 원장에 기록
        │
        └─ shorts_domain.rules_for_config()  →  DomainRules
                 │
    ┌────────────┼─────────────────────────────────┐
    ▼            ▼                                 ▼
 렌더러       upload_package                     political_cta
 resolve_emotion_type()   is_clash_frame(t, cat)   lint_cta(cta, cat)
 resolve_bg_colors()      has_outcome_frame(t, cat)
 gate_domain_words()      lint_topic_frame(t, cat)
 domain_warnings()        lint_yt_title(t, persons, cat)
                          resolve_pinned_comment(cfg)
                          build_upload_package_md()   # 체크리스트
```

**차단 게이트는 `validate_config()` 안에 넣었다** — 렌더를 몇 분 돌린 뒤가 아니라
시작 시점에 실패해야 하기 때문. `render_political_v2_1.py` / `_v2_2.py` 양쪽 동일.

**정치 규칙은 기존 상수를 그대로 참조**한다(`_CLASH_WORDS`·`_OUTCOME_WORDS`·
`DEFAULT_PINNED_COMMENT`). 값을 복사해 두면 두 곳이 갈라져 035 게이트가 조용히
약해진다.

| 파일 | 역할 |

## 4. 연예쇼츠는 V2.2만 만든다

V2.1(훅만 육성 + TTS 논평)과 V2.2(육성 릴레이) 중 **V2.2 전용**으로 확정했다.

| | V2.1 | V2.2 |
|---|---|---|
| 육성 비중 | 14% | **62~78%** |
| 우리 목소리 분량 | 65% | 39% |
| 명예훼손 노출 | **높음** — 논평이 곧 판단 | 낮음 — 사실 나열 후 시청자 판단 |
| 반론 전달 | 우리가 요약 | **당사자 육성 그대로** |
| 저작권 노출 | 낮음 (클립 1개) | 높음 (클립 4개) |
| 제작 난이도 | 쉬움 | 어려움 |

연예 소재에서 논평 비중이 크면 **논평이 곧 단죄로 읽힌다.** 이를 상쇄하려면
나레이션을 보도체로 되돌려야 하는데, 그러면 030 P3(탈보도체)에서 개선한 것을
잃는다 — **안전하게 만들면 재미없고, 재미있게 만들면 위험한** 구조라 이 소재군에
맞지 않는다고 판단했다.

→ 034 플랫폼 분리(V2.2 유튜브 / V2.1 틱톡)에서 **연예의 V2.1(틱톡) 자리는 비운다.**
정치·경제·사회는 종전대로 병행.

## 5. 설계 결함 1건 — `emotion_type` 기본값

**연예 기본값을 `funny`로 둔 것이 잘못이었다.**

BGM은 `select_bgm_for_script()` 가 `emotion_type` **하나만** 보고 고른다
(`data/bgm/<emotion>_N.mp3`). 그런데 V2.1/V2.2는

- 배경 그라데이션 → `bg_colors`
- 자막 색 → 씬별 `color`

를 따로 지정하므로, **`emotion_type` 은 사실상 BGM 스위치**다. 바꿔도 화면은
그대로고 BGM만 바뀐다.

첫 연예쇼츠(하영 증조부 친일 논란)가 이 기본값을 물려받아 **`funny_2.mp3`
(코믹 BGM)** 로 렌더됐다. 카테고리 기본값은 소재의 톤을 모른다 — 연예는 축하성
소재와 논란성 소재의 톤 차이가 극단적이라 카테고리 단위 기본값 자체가 성립하기
어렵다.

**대응**: 소재 톤으로 직접 지정하도록 지침화하고, 템플릿 3종에 `emotion_type` 을
명시 항목으로 넣었다(연예 템플릿 = `relatable`).

| 소재 톤 | `emotion_type` |
|---|---|
| 사실 전달·중립 검증 | `relatable` |
| 대립·비판·규탄 | `angry` |
| 비극·회한·서사 | `touching` |
| 축하·가벼움 | `funny` — **논란 소재 금지** |

**미해결**: `shorts_domain.py` 의 `entertainment` 기본값은 여전히 `funny` 다.
템플릿을 쓰지 않고 config를 직접 만들면 재발한다. `relatable` 로 바꿀지 판단 필요.

## 6. 성과 계측 (Phase 0)

카테고리별로 쪼개서 볼 수 없으면 확장이 도박이 된다. 그래서 규칙 팩보다 **계측을
먼저** 만들었다.

- 업로드가 수동이라 유튜브에 카테고리가 남지 않는다 →
  로컬 원장 `data/channel_analytics/category_ledger.json` 이 유일한 정답 소스.
  `upload_package.md` 생성 시 `{제목: category}` 자동 기록.
- 과거 편은 제목 키워드로 백필(한/영, 해시태그를 신호로 사용). 미분류 2%.
- `analyze_channel_performance.py` 가 카테고리별 표 + 희석(<70%)/확대(≥130%) 경고 출력.

**기준선 (2026-08-05, 88편 백필)**

| 카테고리 | 편수 | 중앙값 | 전체 대비 |
|---|---|---|---|
| political | 73 | 1,174 | 100% |
| economic | 11 | 1,172 | 100% |
| society | 2 | 948 | 81% |

카테고리로는 **아직 아무 차이가 없다**. 연예는 이 1,17x 선을 넘어야 의미가 있고,
넘지 못하면 편성을 접는 근거가 된다.

## 8. 개발 중 알게 된 것

**034 보도체 게이트는 카테고리 공통이다.** `~했다` 류 과거형 어미를 차단하는데,
경제·연예의 서사형 제목("영끌족은 웃었다")도 걸린다. 정치에서 검증된 게이트를
신규 카테고리 편의를 위해 풀지 않고, **제목을 명사로 닫도록** 템플릿·README에
명시하는 쪽을 택했다.

**configs 서브폴더 분리는 하지 않았다.** 036 계획에는 있었지만, 기존 config 37개와
문서·메모리가 전부 현재 경로를 참조해 이동 비용만 크고 얻는 게 없다.
